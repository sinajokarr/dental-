## ۱. فازها

| فاز | هدف | خروجی کلیدی | Milestone |
|---|---|---|---|
| **A — Foundation** | زیرساخت توسعه | Repository، Next.js، Django، PostgreSQL، i18n، توکن‌ها، تست‌ها | M1: پروژه در هر ۴ زبان build می‌شود و تست‌ها سبزند |
| **B — Design System** | زبان بصری قابل استفاده | فونت‌ها، Glass، Nav، دکمه‌ها، Layout، Motion و Gallery | M2: **Gate G1**، تأیید بصری Gallery |
| **C — Homepage** | صفحه اصلی کامل | Hero سه‌بعدی و همه سکشن‌ها | M3: **Gate G3**، تأیید Hero روی دستگاه واقعی |
| **D — Backend** | Pipeline ثبت Lead | API، Admin امن، Telegram | M4: Lead از API تا Admin و Telegram (mock) |
| **E — Conversion** | فرم و WhatsApp | فرم کامل، Server Action، رضایت | M5: ثبت Lead از سایت، end-to-end در ۴ زبان |
| **F — Multilingual** | محتوای چهارزبانه و SEO | متن‌ها، ترجمه‌ها، hreflang، sitemap | M6: **Gate G4**، تأیید متن مرجع؛ ترجمه‌ها بازبینی‌شده |
| **G — Inner Pages** | صفحات داخلی | سه خدمت، International، Consultation، About، صفحات حقوقی، 404 | M7: همه صفحات Phase 1 |
| **H — Quality & Launch** | کیفیت و انتشار | تست‌ها، زیرساخت Production، Deploy | M8: **Gate G5**، امضای Launch |
| I — Marketing ⏸ | بعد از Launch | GTM و GA4 با Consent Mode، Landing Pageها، Google Ads | — |

> در فاز G، «Landing Pages» brief اصلی با «صفحات داخلی» جایگزین شد، چون Ads به تعویق افتاده است (D-006). Landing Pageهای تبلیغاتی به فاز I منتقل شدند.

## ۲. ترتیب و مسیرهای موازی

```text
توسعه:   A ─► B ─► C01 ─► C02 ─► C03 ─► C04…C10 ─┐
               │         ▲                        │
               │        DP1 (خرید مدل)             │
               └──► D ─► E ───────────────────────┼─► G ─► H ─► 🚀
محتوا:   F01 (EN) ─► G4 ─► F02 · F03 · F04 ─► F05 · F06 ──┘           ▲
حقوقی:   متن‌های Q8 و Q12 ─► E04 · G08 ─────────────────────────────┤
Asset:   DP1 ─► Blender ─► GLB · poster · renderها (C02) ─► DP2       │
زیرساخت: تصمیم میزبانی (Q6) + دامنه ─► H06 · H07 ─────────────────────┘
```

**Critical path:** A ← B ← **C02 (وابسته به DP1 و کار Blender)** ← C03 ← H. در کنار آن، **دامنه، منطقه میزبانی و متن‌های حقوقی** پیش‌نیاز H07 هستند.

**کار موازی:**

- فاز D (Backend) بعد از A04 مستقل از B و C پیش می‌رود.
- تهیه متن‌ها (F01) می‌تواند هم‌زمان با فاز C شروع شود.

## ۵. پروتکل اجرا (قوانین ۱ تا ۶)

1. **قبل از هر فاز:** برنامه اجرایی همان فاز ارائه و تأیید می‌شود.
2. **بعد از هر Task** این گزارش ارائه می‌شود:
   - Task ID
   - Status
   - Files Changed
   - Implementation Summary
   - Tests Executed
   - Test Results
   - Known Issues
   - Next Task
3. **تست اجرانشده** صریحاً `NOT RUN` نوشته می‌شود.
4. **بعد از هر تصمیم فنی:** `DECISIONS.md` به‌روز می‌شود.
5. **بعد از هر Task:** `TASK_TRACKER.md` به‌روز می‌شود.
6. **Git:** هر Task در یک commit مستقل (یا چند commit کوچک) ثبت می‌شود و پیام commit شامل Task ID است.
